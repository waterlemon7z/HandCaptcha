# HandCaptcha
Group B 2026-2 Term Project

웹캠으로 인식한 손동작으로 숨은그림찾기 문제를 푸는 **컴퓨터 비전 기반 CAPTCHA**입니다.
배경에 숨겨진 물체를 검지로 가리켜 정답을 제출하고, 손의 이동 궤적과 영상으로 실제 사람의 손인지 판별하는 방식을 실험합니다.

## 프로젝트 소개

HandCaptcha는 문제 생성, 자동 풀이를 이용한 난이도 검수, 손 인식, 진위검출을 하나의 PySide6 GUI에 연결합니다.

- **문제 생성:** 배경 사진에 정답 물체 1개와 방해 물체 2개를 합성해 1280×720 문제를 만듭니다. 회전·크기 조절·부분 가림·라플라시안 피라미드 블렌딩을 적용합니다.
- **난이도 검수:** ORB/SIFT 특징점 매칭 또는 참조 이미지 기반 OWLv2로 자동 풀이를 시도합니다. 검수기가 정답을 찾으면 최대 5회까지 생성하며, 모두 풀리면 마지막 문제를 사용합니다.
- **손 인식:** MediaPipe Hand Landmarker로 검지 끝을 추적하고, 손동작으로 기록 시작과 정답 제출을 처리합니다.
- **진위검출:** 손 떨림, 프레임 차이, Harris 코너와 피라미드 LK 광학 흐름, 기하 변환 오차, CNN을 이용해 실제 손과 합성 영상을 구분합니다.
- **GUI:** 문제·참조 이미지·손 커서·판정 상태를 표시하며, 카메라와 문제 생성·인식 작업을 별도 스레드에서 처리합니다.

현재 GUI의 성공·실패 표시는 **정답 여부**를 기준으로 합니다. 정답을 맞히면 진위검출도 실행하지만, 그 결과는 콘솔에 출력하며 GUI의 최종 판정에는 아직 반영하지 않습니다.

## 사용 시나리오

1. 프로그램을 실행하면 문제와 찾아야 할 물체의 참조 이미지가 표시됩니다.
2. 손을 웹캠에 보여 화면의 커서를 확인합니다.
3. **주먹을 쥐었다가 검지를 펴면** 이동 기록이 시작됩니다.
4. 검지로 정답 물체를 가리키고 **1초 동안 멈추면** 자동으로 제출됩니다. 기본 멈춤 기준은 해당 구간의 이동 범위가 15px 미만인 경우입니다.
5. 멈춘 위치 주변 영역과 정답 영역의 IoU로 정답을 판정합니다. 기본 기준은 0.3 이상이며, 손 입력 오차를 고려해 정답 박스를 사방으로 16px 확장한 경우도 허용합니다.
6. 결과를 확인하고 `confirm` 버튼을 누르면 다음 문제를 생성합니다.

기록 중 손이 0.5초 이상 보이지 않거나 문제 이미지 밖으로 나가면 기록이 취소됩니다. 풀이 중 `refresh` 버튼으로 새 문제를 요청할 수 있고, 검수 방식 선택은 다음 문제 생성부터 적용됩니다. 기본 검수 방식은 `ORB/SIFT`입니다.

## 검출 성능

### 자동 풀이 성능

배경에 대상 하나를 합성한 통제 실험에서 각 조건을 seed 100개로 평가했습니다. 아래는 **가림이 없는 조건**의 정답률이며, 대상 크기는 회전 전 긴 변 기준입니다.

| 대상 크기 | ORB | SIFT | ORB/SIFT 합집합 | OWLv2 |
|---|---:|---:|---:|---:|
| 약 58px | 0% | 4% | 4% | 40% |
| 약 115px | 1% | 33% | 34% | 72% |
| 약 173px | 21% | 53% | 54% | 81% |

이 표의 정답률은 자동 풀이 알고리즘이 대상을 찾은 비율입니다. 주 판정은 생성기의 IoU 기준을 사용하며, ORB/SIFT 합집합은 최대 2개 후보를 허용하는 앙상블입니다. 방해 물체와 자연 가림이 포함되는 실제 문제 생성 조건과는 차이가 있습니다.

### 진위검출 성능

규칙과 CNN을 함께 적용한 결과입니다.

| 평가 대상 | 표본 수 | 사람 판정 | 봇 판정 | 재측정 |
|---|---:|---:|---:|---:|
| 실제 사람 손 | 89 | 81 | 2 | 6 |
| 좌표 봇 | 40 | 0 | 40 | 0 |
| 합성 영상 봇 | 64 | 0 | 64 | 0 |

좌표 봇과 합성 영상 봇 104개를 모두 차단했으며, 사람을 봇으로 판정한 비율은 2/89(약 2.2%)였습니다. 사람 데이터는 1명이 여러 조건에서 녹화한 자료이고, 합성 봇의 손·배경도 제한적이므로 다양한 사용자와 실제 공격 환경에 대한 일반화 성능은 추가 검증이 필요합니다. 이 결과는 모듈 단위 평가이며 현재 GUI의 인증 성공률을 의미하지 않습니다.
