# 진위검출 (bot_detection)

캡차를 푸는 손이 **진짜 사람 손인지, 손 사진을 움직인 합성 영상(봇)인지** 판별한다.
손 인식(`cv/hand_tracking`)이 `done`을 내면 그 `HandResult`를 받아 **사람 / 봇 / 재측정** 중 하나로 답한다.

> 담당: 정지훈 · 최종 갱신: 2026-11-07

---

## 1. 무엇을 막나 (위협 모델)

| 공격 | 처리 |
|---|---|
| 녹화해 둔 진짜 손 영상 재생 | 정답 위치가 매번 랜덤이라 문제 생성 모듈이 막음 |
| **합성 손 영상 봇**: 정답은 AI로 찾고, 손 사진을 그 위치로 움직인 영상을 가상 카메라로 주입 | **진위검출이 막는 대상** |
| 앱 코드를 고쳐 좌표 직접 주입 | 범위 밖 (로컬 앱이라 검사 자체를 건너뛸 수 있음) |
| 손가락을 따로 움직이는 3D 손 렌더링 | 한계 (아래 7절) |

원칙: **보수적** — 사람을 봇으로 오판하지 않는 것이 우선. 각 검사는 확실한 봇만 거른다.

---

## 2. 판정 구조

```
HandResult (raw_trajectory, timestamps, frames=검지 끝 128×128 crop, frame_timestamps, frame_size)
   │
   ├─ 1단계 궤적 검사 (trajectory.py) ─────────── 걸리면 봇
   ├─ 2단계 영상 검사 (frame_check.py)
   │    ① 배경 시간 노이즈 ───────────────────── 걸리면 봇
   │    ②' 손 변형 (변환 맞춤 오차) ──────────── 걸리면 봇
   ├─ 3단계 CNN (cnn/runtime.py) ─────────────── 걸리면 봇
   └─ ②'를 잴 데이터가 부족하면 ──────────────── 재측정
                                               나머지 → 사람
```

하나라도 걸리면 봇이다. 결과는 세 가지:

| 반환 | 뜻 | 앱에서 할 일 |
|---|---|---|
| `True` | 사람 | 통과 |
| `False` | 봇 | 실패 처리 |
| `None` | 재측정 | "손을 조금 더 크게 움직여 다시 해주세요" 안내 후 다시 기록. **2번 연속이면 실패** |

### 1단계: 궤적 검사 (`trajectory.py`)
궤적을 끝에서 15px 안에 머문 **멈춤 구간**과 그 앞의 **이동 구간**으로 나눈다.
- `jitter_rms`: 멈춤 구간 좌표 − 가우시안 스무딩 = 고주파(손 떨림) 성분의 RMS (px). 사람은 멈춰도 미세하게 떨린다 **(03강 가우시안 필터 연장)**
- `jitter_lag1`: 떨림의 이웃 프레임 자기상관. 프로그램이 넣은 백색 노이즈는 음수
- `straightness`: 직선거리 / 경로 길이. 봇 경로는 1에 가깝다

### 2단계: 영상 검사 (`frame_check.py`)
crop 창 위치(카메라 px)는 `raw_trajectory`와 `frame_size`로 거꾸로 계산한다.

- **① 배경 시간 노이즈** `zero_ratio`: 멈춤 구간에서 창 위치가 같은 연속 두 장의 `absdiff`가 정확히 0인 픽셀 비율. 진짜 웹캠은 센서 노이즈 때문에 낮고, 사진을 붙인 합성 영상은 높다 **(02-2 프레임 차이)**
- **②' 손 변형** `affine_res`: 이동 구간 연속 crop에서 Harris 코너 → 피라미드 LK 옵티컬 플로우(앞→뒤 추적 검증) → crop 안에서 거의 안 움직인 점 = 손. 그 점들의 이동을 **회전+확대+이동 변환 하나**로 맞춘 뒤 남는 오차 중앙값 (`cv2.estimateAffinePartial2D`, LMEDS). 사진을 돌리고 키운 합성은 변환 하나로 설명돼서 ≈0, 손가락이 따로 굽는 진짜 손은 오차가 남는다 **(04강 Harris + 03강 피라미드 + 02-2 기하 변환 연장)**
- 쓰지 않는 crop 쌍: 시간 간격 > 0.15초(중간 프레임 놓침), 픽셀까지 똑같은 중복 프레임(1280×720에서 카메라가 같은 프레임을 두 번 줌), 크기가 깨지거나 전부 검정인 crop

### 3단계: CNN (`cnn/`)
②'와 같은 질문("손가락이 따로 움직이나, 사진 한 장이 통째로 움직이나")을 **학습으로** 보게 한 작은 CNN **(05~07강 CNN)**.
- 입력: 이동 구간 crop을 초당 12장으로 다시 뽑아 연속 10장을 64×64 흑백으로 → **10채널로 겹쳐** 2D CNN에 넣음
- 모델: Conv 블록 3개(32→64→128, 각 Conv-BN-ReLU ×2 + MaxPool) + 전역 평균 풀링 + Dropout + 출력 2. 파라미터 29만 개
- 녹화 점수 = 10장 묶음(5장씩 밀며)들의 가짜 확률 중앙값. 묶음이 안 나오면 CNN만 생략
- 앱에서는 **PyTorch 없이** `model.onnx`를 `cv2.dnn`으로 실행 (PyTorch 결과와 차이 < 1e-8)

#### CNN 학습 과정 (Kaggle 노트북 `stophoon2/handcaptcha-cnn`)
사람 데이터가 부족해서, 1300명 넘는 사람이 각자 웹캠으로 찍은 손동작 데이터셋 **20BN-Jester**(176×100, 12fps)를 썼다.

| 단계 | 스크립트 | 내용 | 결과 |
|---|---|---|---|
| 0 | `jester_check.py` | 저해상도에서 MediaPipe가 손을 연속 10장 잡는지 확인 | 클립의 55%에서 가능 → 진행 (확대는 효과 없음) |
| 1 | `jester_prep.py` | **진짜 샘플**: 검지 끝 중심 crop 연속 10장 (손이 움직이는 구간, crop 크기 = 손 크기 × 1.2~2.5 랜덤) | 클립 4000개 → 3041개 |
| 2 | `make_fake.py` | **가짜 샘플**: 진짜 샘플마다 짝 1개. 같은 클립 한 프레임에서 손만 오려(마스크 경계는 가우시안으로 부드럽게) 손 없는 다른 클립("No gesture") 배경 위에서 **진짜와 같은 경로·같은 crop 크기**로 이동. 70%는 매 장 회전·확대(S4형), 30%는 센서 노이즈 추가, JPEG 재압축 | 3041개 |
| 3 | `train.py` | 학습/검증을 **클립 단위**로 9:1 분리. 증강은 진짜·가짜에 똑같이(좌우·시간 뒤집기, 밝기·대비, 노이즈, JPEG) → 압축 흔적·밝기 같은 꼼수 대신 움직임을 보게 함. AdamW + OneCycle, 20에폭, GPU 69초 | 아래 표 |
| - | `export_onnx.py` | `model.pt` → `model.onnx` | |
| - | `infer.py` | 우리 녹화·합성 봇으로 평가 (PyTorch) | 아래 표 |

**Jester 검증 세트** (진짜 296, 가짜 296)

| 문턱(가짜 확률) | 정확도 | 사람 오판 | 가짜 검출 (S1형 / S4형) |
|---|---|---|---|
| 0.5 | 94.8% | 4.7% | 94.3% (98.8 / 92.6) |
| **0.976** (사람 오판 ≤1%가 되도록 검증 세트에서 계산) | – | 0.7% | 81.8% (95.0 / 76.9) |

## 3. 기준값과 근거 (`detector.py` 상수)

| 상수 | 값 | 봇 조건 | 근거 (사람 89개 / 합성 봇 64개) |
|---|---|---|---|
| `JITTER_MIN` | 0.4 px | `jitter_rms` < 0.4 | 사람 최소 0.48. 합성 S1 일부(0.27~)만 해당 — 좌표 봇용 |
| `STRAIGHT_MAX`, `LAG1_MIN` | 0.95, −0.3 | 곧음 > 0.95 **그리고** lag1 < −0.3 | 사람 중 (0.91, −0.27)이 있어서 좁힘 |
| `ZERO_MAX` | 0.65 | `zero_ratio` > 0.65 | 사람 최대 0.59. 합성 S1 0.49~0.82, S2 0.55~0.65 (1280×720에선 간격이 좁아짐, 아래 8절) |
| `AFFINE_MIN` | 0.08 px | `affine_res` < 0.08 | **사람 최소 0.33, 합성 봇 최대 0.06** (S1~S4 전부) — 가장 확실한 기준 |
| `AFFINE_MIN_PAIRS` | 5 | 쌍이 5개 미만이면 ②' 측정 불가 → 재측정 | 2쌍으로 재면 사람이 0.04까지 떨어짐 |
| `CNN_THRESHOLD` | 0.976 | CNN 가짜 확률 > 0.976 | Jester 검증에서 사람 오판 ≤1%. 우리 데이터: 사람 2/80, 합성 봇 59/64 |
| `MAX_RETRY` | 2 | 재측정 2번 연속이면 실패 | 통과로 하면 봇이 일부러 짧게 움직여 뚫음 |
| `frame_check.MAX_GAP` | 0.15 s | 이보다 벌어진 crop 쌍은 안 씀 | 보통 간격 0.03~0.047초 |
| `frame_check.HARRIS_QUALITY` | 0.001 (코너 150개) | | 0.01일 때보다 어두운·먼 손에서 코너 확보 (사람 재측정 8 → 3) |

## 4. 현재 성적표

데이터
- 사람 89개: 본인, 640×480 25개 + 1280×720 64개. 오른손·왼손, 빠르게·느리게, 길게·짧게, 조명·거리를 바꿔 찍음
- 좌표 봇 40개: 영상 없이 좌표만 (직선·곡선·노이즈·순간이동 4종 × 10)
- 합성 영상 봇 64개: 1280×720, 종류별 16개 (`synth.py`). 실제 찍은 손 사진(팔뚝까지 오림) 2장 × 배경 11장, 손 크기 170~260px, 1.5~3초 이동

| 종류 | 만드는 법 |
|---|---|
| S1 | 손 사진을 그대로 옮기기만 |
| S2 | S1 + 경로에 부드러운 떨림 (사람 손 떨림 흉내) |
| S3 | S2 + 화면 전체에 센서 노이즈 (진짜 카메라 흉내) |
| S4 | S3 + 매 장 손 사진 회전·확대 (손 모양 변화 흉내) |

**최종 판정 (규칙 + CNN)**

| 그룹 | n | 사람 | 봇 | 재측정 |
|---|---|---|---|---|
| 사람 | 89 | 81 | 2 (2.2%) | 6 |
| 좌표 봇 | 40 | 0 | **40** | 0 |
| S1 | 16 | 0 | **16** | 0 |
| S2 | 16 | 0 | **16** | 0 |
| S3 | 16 | 0 | **16** | 0 |
| S4 | 16 | 0 | **16** | 0 |

- 봇 104개 전부 차단, 판정 1회 약 0.1~0.3초 (CPU)
- 사람 재측정 6개는 전부 짧게 움직인 녹화. 재측정을 2번 연속으로 받지 않는 한 통과
- 사람을 봇으로 본 2개는 **CNN 때문** (둘 다 예전 640×480 녹화, 가짜 확률 0.986·0.989)

**규칙 vs CNN 따로 보기** — 두 방법이 서로 독립적으로 같은 봇을 잡는지 (교차 검증)

| 그룹 | 규칙만: 봇 판정 | CNN만: 가짜 확률 > 0.976 | CNN 점수 중앙값 |
|---|---|---|---|
| 사람 89 | 0 (재측정 6) | 2 / 80 (10장 묶음 나온 것) | 0.052 |
| S1 16 | 16 | 16 / 16 | 1.000 |
| S2 16 | 16 | 14 / 16 | 1.000 |
| S3 16 | 16 | 16 / 16 | 1.000 |
| S4 16 | 16 | 13 / 16 | 1.000 |

- 규칙은 사람 오판 0으로 봇 64개를 전부 잡는다. CNN은 Jester로만 학습했는데도 **우리 합성 봇 64개 중 59개(92%)**를 따로 잡았다
- 두 방법이 거의 같은 답을 낸다 → 손 사진이 "통째로 움직인다"는 단서가 실제로 유효하다는 근거
- CNN을 같이 쓰면 이번 데이터에서 더 잡는 봇은 없고 사람 오판이 2개 늘어난다. 규칙이 못 잡는 새 공격이 나올 때를 대비한 두 번째 검사로 둔다

## 5. 사용법 (`worker.py` 연동)

```python
from backend.bot_detection.detector import check, MAX_RETRY

is_human, reason = check(result)        # result: state == "done" 인 HandResult
if is_human is True:
    ...                                  # 통과
elif is_human is False:
    ...                                  # 봇 → 실패 처리
else:                                    # None = 재측정
    retry_count += 1
    if retry_count >= MAX_RETRY:
        ...                              # 실패 처리 (통과시키면 안 됨)
    else:
        ...                              # "손을 조금 더 크게 움직여 다시 해주세요" 표시 후 tracker.reset()
```
- `reason`은 사람이 읽는 설명 (로그·디버그용)
- 정답 판정(`generator.solve`)이 맞았을 때만 호출하면 된다
- `cnn/model.onnx`가 없으면 CNN 검사만 자동으로 빠진다

## 6. 실행 명령 (레포 루트, `.venv`)

```bash
# 사람 녹화 (주먹 → 검지 펴기 → 이동 → 1초 멈춤 → 자동 저장, q 종료 / r 버리기)
python cv/hand_tracking/download_model.py           # 처음 한 번 (MediaPipe 모델)
python -m backend.bot_detection.record              # → test/data/human/

# 봇 데이터 만들기
python -m backend.bot_detection.mock                # 좌표 봇 → test/data/bot/
python -m backend.bot_detection.synth               # 합성 영상 봇 S1~S4 → test/data/synth/

# 판정기 전체 평가 (사람·좌표 봇·합성 봇)
python -m backend.bot_detection.detector

# 특징값 분포 보기
python -m backend.bot_detection.trajectory
python -m backend.bot_detection.frame_check

# CNN (개발용, PyTorch 필요: pip install torch onnx)
#   학습은 Kaggle 노트북: jester_prep.py → make_fake.py → train.py (각 파일 맨 위 설명 참고)
python -m backend.bot_detection.cnn.infer --jester <Kaggle 결과 폴더>   # 우리 데이터로 평가
python -m backend.bot_detection.cnn.export_onnx                         # model.pt → model.onnx
```
- `test/data/human/`, `test/data/synth/`는 웹캠 영상이 들어 있어서 git에 안 올림 (로컬 보관)
- `cnn/model.pt`, `cnn/*.npz`도 git 제외. 앱에 필요한 건 `cnn/model.onnx`(1.1MB)뿐

## 8. 한계

- **사람 데이터가 1명**: 손·속도·조명·거리를 바꿔 89번 찍었지만, 다른 사람 손은 검증하지 못했다
- **CNN 도메인 차이**: Jester(세로 100px)에서 배운 기준이 우리 웹캠(1280×720)에 완전히 맞지는 않는다. 사람 오판 2개가 모두 예전 640×480 녹화의 길고 빠른 이동에서 나왔다. 우리 데이터로 미세조정하면 나아질 수 있지만 사람 데이터가 적다
- **① 배경 노이즈 검사가 1280×720에서 약해짐**: 화면이 커서 손이 조금만 떨려도 crop 위치가 바뀌어 "위치가 같은 두 장"이 잘 안 나오고(사람 89개 중 18개 측정 불가), 합성 S2와 사람의 간격도 좁아졌다(사람 최대 0.59, S2 0.55~0.65). 지금은 ②'가 합성 봇을 전부 큰 차이로 잡고 있다
- **합성 봇 재료**: 손 사진 2장(같은 사람)·배경 11장으로 만든 것이라 다양성이 제한적이다
